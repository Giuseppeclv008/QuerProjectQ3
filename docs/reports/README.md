# Committed reports — what is current, and what is not

These four directories are committed artifacts: a reader opens them expecting
the numbers to be the ones this code produces. Three fixes landed after they
were last generated, and the rebuilt 3-month store (`scripts/build_store.sh` →
`events_3mo.duckdb` at the repository root) is not in the repo, so they could
not be regenerated in the same commit that invalidated them.

Recording that in commit messages alone is not enough: a reader browsing this
directory never sees them, and gets the pre-fix claim stated with full
confidence. This table is the record. Each affected `report.md` also carries a
banner at the top pointing back here.

| Artifact | Invalidated by | What changes on regeneration |
|---|---|---|
| `kpi-2026-02/report.md` — "22,459 sustained no-load periods, 11,551.3 head-hours" | `6e1b9be` — a hole in the data ends an idle run instead of being counted as one | Head-hours **fall**, by however much of the total was a switched-off machine's off-window absorbed into a surrounding run. The assumptions block gains the `idle_max_gap_seconds` (600 s) declaration. |
| `anomalies-2026-02/anomalies_over_time.png` and the itemised hits behind it | `0a88fac` — the itemised anomaly sample spans the period instead of its first hours | The scatter **spreads across all 28 days**. Counts are unchanged: they were always exact, and only the sample the figure is drawn from was skewed. |
| `drift-2026-02_2026-04/report.md` — "All 36 heads track each other closely …; none is out of step" | `baa4819` — the head-correlation ranking says it sees shape, not level | The sentence is **replaced**: correlation over these series measures shared shape, so it cannot support "none is out of step", which is a claim about level. |
| `ask-live-sample/report.md` — same sentence | `baa4819` | Same. This directory is also the live-agentic-path evidence (`docs/validation-log.md`); regenerating it needs Ollama up, not just the store. |

The `.html` twin of each `report.md` carries the same stale content and the same
banner, and is regenerated by the same command.

## Regenerating

From the repository root, with the raw month zips present:

```bash
scripts/build_store.sh events_3mo.duckdb telemetry_*.zip   # out path is required
scripts/demo.sh                                            # kpi, anomalies, drift
```

`build_store.sh` takes the output path as its first argument and exits on its
own usage line if given none. `demo.sh` defaults to `events_3mo.duckdb` at the
repository root and writes into this directory, replacing each report — which
removes its banner along with the stale numbers.

`ask-live-sample/` additionally needs a reachable model — see
`docs/validation-log.md` for the run that produced the committed copy and the
provider settings it used.

When a directory is regenerated, delete its row here. `demo.sh` rewrites both
`report.md` and `report.html`, so their banners go with the stale numbers and
need no separate removal. An empty table means the committed reports match the
code.
